# Map the project context

Use the project already selected by the user. Locate these records where they
actually live; the names below describe their purpose, not required filenames.

| Record | Minimum useful content |
|---|---|
| Current task | Question or proposed change; expected outcome; selected repository/ref |
| Evidence | Existing results and failures, evidence class, immutable source/data identities |
| Evaluation | Baselines, acceptance criteria, split/freeze rules, unknown measurements |
| Execution | Applicable permission, one existing allowance/ledger, stop conditions |
| Validation | Commands and expected outcomes; unavailable dependencies or reviewers |
| Continuity | Current decisions and where to append new findings |

Only load records needed for the requested work. A read-only integration review
does not need an inference allowance if no inference is planned. Missing records
limit the claims/actions they support; do not invent evidence to fill a template.

For an existing Aldertrace study, use its `docs/domains/jev/MEMORY.md`, relevant
`LOG.md` entries, current protocol/amendment, instrument README and original goal
and budget ledger. Resume them. This template is not a replacement ledger.

For a genuinely new, user-requested project, draft its initial context explicitly
as a new plan. Do not assume any prior result, permission or spending allowance.
If execution prerequisites are absent, continue read-only analysis or offline
synthetic demonstration and identify what is needed before dependent execution.

The collection's `examples/` directory provides a self-contained synthetic
starting example. It requires no private Aldertrace notes, service or credentials.
Its programmed recommendations and assigned token values are teaching material.
